TASK #28 - Sicurezza: gestione password admin e segreti
========================================================
TIPO:     Indurimento sicurezza
PRIORITÀ: Media
STATO:    Da fare

DESCRIZIONE:
Tre debolezze correlate:
1) Confronto password con === (non constant-time) → possibile timing
   attack teorico (server.js:859).
2) La password admin viene salvata in localStorage (index.js:130,
   settings.js:284): persistente, leggibile da qualsiasi XSS (vedi
   task #05) e sincronizzata tra sessioni.
3) GET /api/settings restituisce il token Telegram IN CHIARO a chi
   conosce la password; sufficiente per l'esfiltrazione del bot.

POSIZIONE:
- server.js:852-864 (requireAdminPassword)
- public/index.js:117-131, public/settings.js:201-210,284
- server.js:984-987 (GET /api/settings con token in chiaro)

SOLUZIONE PROPOSTA:
Usare crypto.timingSafeEqual; valutare sessionStorage o cookie
httpOnly di sessione; mascherare il token nelle GET (es. ultimi 4
caratteri) e accettarlo solo in POST/test quando modificato.
